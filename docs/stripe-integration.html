Stripe products needed

Setup first
One Stripe account covers everything. The account is registered under your business domain offcutchallenge.co.uk — this is purely your business identity for Stripe's compliance review. It has no technical effect on where payments flow or where webhooks point. The marketplace app (Vercel), the public storefront, and future products like the camera app all operate through the same account using the same API keys.

Account architecture

Stripe Account  (business: offcutchallenge.co.uk)
│
├── Products
│     ├── Offcut Challenge Membership  — £29/month subscription
│     └── Camera App                  — one-off purchase (future)
│
├── Stripe Connect  — marketplace seller accounts (Express)
│     └── Each workshop seller gets their own Express sub-account
│
└── Webhook endpoints  (multiple allowed)
      ├── https://offcut-challenge.vercel.app/api/webhooks/stripe
      │     └── handles: subscriptions, marketplace payments, Connect events
      └── https://offcutchallenge.co.uk/api/webhooks/stripe  (future)
            └── handles: camera app purchases

🔗 Stripe Connect

The core of the marketplace. Allows buyer payments to flow through Offcut Challenge (platform) and out to sellers, with the 5% fee taken automatically.

Account type: Express — minimal friction for sellers. Stripe handles KYC and bank details. Sellers get a Stripe Express dashboard.

Charge type: Destination charges — the payment appears on the Offcut Challenge platform account, with a transfer to the seller.

💳 Stripe Billing

Handles the £29/month subscription for workshops 31 and onwards. Legacy workshops (first 30) are flagged in the database and never hit this flow.

Product: One product — "Offcut Challenge Membership" with one recurring price of £29/month.

Gate: The app checks subscription status on protected routes.

⚡ Stripe Webhooks

How Stripe tells your app that something happened — payment succeeded, subscription cancelled, seller account approved, etc.

Two webhook endpoints registered in the same account — one for the Vercel app, one for the offcutchallenge.co.uk storefront when it's built.

Verification: Every event must be verified using the webhook signing secret before being acted on. Each endpoint has its own unique signing secret.

Before writing any code: Register a Stripe account at stripe.com using offcutchallenge.co.uk as your business website, then apply for Connect platform access (Stripe → Settings → Connect). This can take 1–3 business days to be approved. Do this first — everything else is blocked on it.

Add a subscription_status column to the workshops table with these possible values:

Status value Meaning Has access?

How the 5% fee works

Stripe Connect

Destination charge — example £100 sale

£100
Buyer pays
→
Payment Intent
£5.00
Platform keeps (5%)
minus Stripe fees ~£1.74
→
Auto transfer
£95.00
Seller receives (95%)
How this works in the Stripe API: When creating a PaymentIntent, set application_fee_amount to 5% of the total (in pence) and transfer_data.destination to the seller's Stripe Connect account ID. Stripe handles the split automatically.

Stripe's own fees (typically 1.4% + 20p for UK cards, or 2.9% + 30p for international) come out of the platform's application fee share — not the seller's. If Stripe's fee on a £100 sale is ~£1.60, your net is ~£3.40 on that transaction. Factor this into your pricing model as you grow.

PaymentIntent creation (simplified)

// Server Action: createPurchaseIntent(listingId, quantity)
const feeAmount = Math.round(totalPence * 0.05)  // 5%

const paymentIntent = await stripe.paymentIntents.create({
  amount:                  totalPence,
  currency:                'gbp',
  application_fee_amount:  feeAmount,             // platform takes this
  transfer_data: {
    destination:           seller.stripe_account_id,  // seller's Connect account
  },
  metadata: {
    listing_id:  listing.id,
    order_qty:   quantity,
    buyer_id:    buyerWorkshopId,
    seller_id:   sellerWorkshopId,
  }
})

Subscription gate — where to check

Add a helper function requiresActiveSubscription(workshop) and call it in any server component or action that touches marketplace features. It returns true if the workshop has legacy_free, active, or trialing status.

/dashboardYes — stock management requires active subscription

Never mark an order as paid until the webhook fires. The Stripe Checkout success page redirect is not reliable — users can close their browser or lose connection. The payment_intent.succeeded webhook is the only authoritative confirmation. Always gate fulfilment on the webhook, not the redirect.

Business rules for offers

RuleDetail
Offer must be below list priceEnforced server-side — reject if offered_price_pence ≥ listing price
One active offer per buyer per listingBlock new offer if there's already a pending/countered offer for this buyer/listing combo
Expiry48 hours from creation or last counter — whichever is more recent
Max counter roundsRecommend 5 total back-and-forths before forcing a decision (prevents indefinite loops)
Accepted but not paidIf buyer doesn't pay within 24h of acceptance, offer auto-expires and listing returns to active
5% feeAlways applied at the agreed price — buyer saves by offering less, seller earns less, platform always takes 5%
Workshop can't offer on own listingEnforce server-side: buyer_workshop_id ≠ listing.workshop_id

Webhook events to handle

Route: /api/webhooks/stripe
All webhooks must be signature-verified first: Use stripe.webhooks.constructEvent(rawBody, signature, STRIPE_WEBHOOK_SECRET) before touching any event data. A missing or invalid signature means the request is not from Stripe — return 400 immediately.
Event
What to do
payment_intent.succeeded
A buyer has successfully paid.
→ Read listing_id & order_qty from metadata. Update order status to 'paid'. Reduce listing quantity. Mark stock sold if qty hits 0. Email seller and buyer.
payment_intent.payment_failed
Card declined or payment failed.
→ Update order status to 'payment_failed'. Email buyer to retry. If from an offer, mark offer as 'payment_failed' so seller knows to re-offer or relist.
customer.subscription.created
New subscription started (workshop 31+).
→ Set workshop.subscription_status = 'active'. Save stripe_subscription_id. Grant full access.
customer.subscription.updated
Subscription changed status (e.g. payment failed → past_due).
→ Sync the new status to workshop.subscription_status. Show appropriate banner in dashboard.
customer.subscription.deleted
Subscription cancelled or not renewed.
→ Set subscription_status = 'cancelled'. Block marketplace access (but preserve data). Send "we're sorry to see you go" email.
invoice.payment_failed
Monthly subscription payment failed.
→ Set subscription_status = 'past_due'. Email workshop: "Your payment failed — please update your card." Stripe will retry automatically over the next few days.
account.updated (Connect)
A seller's Express account details changed — most importantly when they finish onboarding.
→ If event.data.object.charges_enabled === true: set workshop.stripe_onboarding_complete = true. Show "Payments ready" in settings.
checkout.session.completed
Stripe Checkout session finished (subscription or purchase).
→ Fallback for subscription flow: if mode = 'subscription', retrieve the subscription and update status. Useful if subscription.created fires before your DB is ready.
Idempotency: Webhooks can fire more than once for the same event (Stripe retries on failure). Always check if you've already processed an event before acting. For orders, check if order.status is already 'paid' before updating it again.

Variable Where to find it Notes

Local webhook testing: Install the Stripe CLI (stripe listen --forward-to localhost:3000/api/webhooks/stripe). This gives you a local signing secret to use in .env.local. The production signing secret is different — set that separately in Vercel.
